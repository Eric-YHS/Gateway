# Legacy 兼容版部署说明

## 环境要求

- Windows Server 2008 R2 或更高
- IIS 7.5 或更高
- .NET Framework 4.7.2
- Visual Studio 2019 或等效 MSBuild 环境

压缩包已带编译后的 `bin` 目录，可以直接按下面步骤挂 IIS。
如果贵司希望先复核源码，也可以先用 VS2019 打开 `GatewayDemo.Legacy.sln` 再重新编译一次。

## 项目结构

- `src/GatewayDemo.Legacy.Web`：统一认证网关
- `src/MockBusinessBackend.Legacy.Web`：本地回归用的配套业务后端站点，可选

## 当前需求边界

当前交付默认按仓库根目录的 [需求边界说明.md](../../需求边界说明.md) 理解：

- 主需求：给现有官方 APP 套网关
- 次需求：浏览器和 APP 都走统一认证
- 非当前主需求：开放给第三方 APP 的自定义接入协议

## 默认端口

- 网关业务入口：`5050`
- 网关管理入口：`5051`
- 本地回归后端：`5055`

## IIS 部署建议

### 1. 部署网关站点

将 `src/GatewayDemo.Legacy.Web` 作为一个独立 IIS 站点部署，并绑定两个端口：

- `http://localhost:5050`
- `http://localhost:5051`

网关代码会根据当前端口判断是否进入管理后台。

### 2. 部署业务后端站点

如果只是验证快普易系列体验站，这一步可以跳过。

如果需要做本地 mock 回归，再将 `src/MockBusinessBackend.Legacy.Web` 部署为单独 IIS 站点：

- `http://localhost:5055`

### 3. 目录权限

给网关站点的应用程序池账号增加以下目录的写权限：

- `src/GatewayDemo.Legacy.Web/App_Data`

原因：

- SQLite 数据库会自动创建在这里
- 浏览器申请、审批、审计数据都落在这里

### 4. 上游站点配置与 profile 切换

当前源码默认已经把 `erp-main` 配成快普易系列体验站：

- `UpstreamBaseUrl = https://j.kuaipu.com.cn:2027/`
- `EntryPath = default.aspx`

#### 4.1 使用 profile 切换（推荐）

仓库已提供 profile 切换机制，不需要手工编辑 JSON：

```powershell
# 切换到公网体验站
powershell -ExecutionPolicy Bypass -File scripts\legacy\set-gateway-profile.ps1 -Profile experience

# 切换到本地演示站（需指定本地演示站 URL）
powershell -ExecutionPolicy Bypass -File scripts\legacy\set-gateway-profile.ps1 -Profile local-demo -DemoBaseUrl http://localhost:80/
```

切换后，`App_Data/gateway-sites.json` 会自动更新。
如需对接本地演示站点，详细步骤见 [本地演示站接入说明.md](./本地演示站接入说明.md)。

#### 4.2 手工修改（备选）

如果要手工切换成别的真实站点，直接修改：

- `src/GatewayDemo.Legacy.Web/App_Data/gateway-sites.json`

每个站点至少要核对这两个字段：

- `UpstreamBaseUrl`
  填真实业务站点的基础地址，例如 `http://127.0.0.1:8080/`、`http://127.0.0.1:8080/ERP/`
- `EntryPath`
  填该站点实际入口路径，例如 `login.aspx`、`Portal/Main`、`Index`

#### 4.3 注意事项

- 不要默认假设所有站点入口都是 `/portal`
- 如果业务站点页面里存在根路径资源，例如 `/Content/site.css`、`/Scripts/app.js`、`/Images/logo.png`，当前网关会自动改写为内部代理路径并继续转发
- 如果业务系统在前端脚本里动态拼接绝对路径或通过脚本发起跳转，仍需要按真实页面再核对一遍
- 快普体验站登录成功后会先进入 `ashx/winCheck.ashx`，再自动打开 `/WebEnterprise/newmain.aspx`
- 如果浏览器拦截弹窗，请允许该站点弹窗，否则会影响进入体验站主页面
## 首次运行

1. 至少先部署 `src/GatewayDemo.Legacy.Web` 到 IIS
2. 如果需要做本地 mock 回归，再额外部署 `src/MockBusinessBackend.Legacy.Web`
3. 打开网关入口：`http://localhost:5050/gateway`
4. 打开管理入口：`http://localhost:5051/admin`
5. 如果需要复核源码，再使用 VS2019 打开 `GatewayDemo.Legacy.sln` 重新编译

如果服务器已经安装 IIS，也可以直接使用样例脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\legacy\setup-demo-sites.ps1
```

## 默认管理账号

- 用户名：`gateway-admin`
- 密码：`GatewayDemo!2026`

## 默认访问路径

- 网关入口：`/gateway`
- ERP 体验站：`/proxy/erp-main/default.aspx`
- ERP API：`/proxy/erp-main/api/ping`
- WMS 东仓：`/proxy/wms-east/portal`
- 财务共享：`/proxy/finance/portal`

说明：

- 浏览器联调通常从 `/proxy/erp-main/default.aspx` 开始
- 现有官方 APP 联调应优先理解为“只改服务器地址，让原有初始化、登录、`SessionKey / userToken`、`WCF / ashx` 链路继续走网关”
- 后台里保留的 `AppKey / AppSecret / HMAC` 页面仅为可选增强项，不是现有官方 APP 的主用方式

## 重置网关数据

如果需要清空网关数据库，可以执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\legacy\reset-gateway-db.ps1
```

## 代理说明

当前交付包默认使用的是网关内置 managed proxy，因此部署时不强依赖 `ARR / URL Rewrite`。

这样做的目的：

- 降低第一次交付的部署复杂度
- 避免客户现场因为缺少 IIS 扩展而无法直接验证
- 保证交付包到手即可运行

如果后续客户现场决定统一切换到 `ARR + URL Rewrite`，可以在不改变业务流程的前提下替换代理实现。

当前 managed proxy 已补齐这些兼容行为：

- 浏览器设备申请审批链路可直接跑通
- 当前 APP 主方向是让现有官方 APP 通过网关访问
- 自定义 APP HMAC 设备凭据链路继续保留，作为可选增强项
- 会透传 `Authorization`、`Cookie` 和自定义业务请求头到后端
- 会保留 `X-Gateway-Site`、`X-Forwarded-For` 等网关侧审计和站点识别头
- 撤销设备授权时，会同时清理该设备已签发的 APP 凭据和重放 nonce
