# GatewayDemo 交付包维护规则

## 唯一交付文件

- 对研发交付的压缩包固定为：`E:\验证页面\deliverables\GatewayDemo.Legacy-net472.zip`
- 后续修复完成并通过自检后，直接原位覆盖该文件。
- 不再在 `deliverables` 中新建带日期、`fixed`、`reviewed`、功能名等后缀的同类 ZIP。

## 更新流程

1. 记录覆盖前压缩包的 SHA-256，但不另建交付副本。
2. 在 `acceptance-runs` 的隔离目录中解压、修改、构建、部署和测试。
3. 候选包通过 Release 构建、真实 IIS、真实浏览器、安全及交付卫生检查后，再原位替换唯一交付文件。
4. 覆盖后重新解压唯一交付文件并复验内容与 SHA-256。
5. 临时候选 ZIP 和本轮创建的 IIS 资源在确认后删除；测试证据保留在 `acceptance-runs`，不得放入交付包。

## 交付卫生

- 压缩包根目录只保留一个 `README.md`，不得包含测试报告、截图、聊天记录或 AI/测试工具相关字样。
- 不得包含真实环境域名、IP、账号、口令、APP Secret、私钥、测试端口或绝对工作路径。
- 本地演示默认值必须可由部署脚本或配置覆盖，并在 README 中明确说明。
