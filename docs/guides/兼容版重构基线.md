# 兼容版重构基线

## 已经开始落地的部分
1. 新增 `src/GatewayDemo.Legacy.Core`，目标框架固定为 `net472`。
2. 新增 `src/GatewayDemo.Legacy.Web`，按 `ASP.NET Web Forms + .aspx + .ashx` 方式起好了兼容宿主骨架。
3. 领域模型已经从当前 `.NET 10` 实现中抽离，后续 Web Forms 宿主、`.ashx` 处理器、ADO.NET 仓储都会依赖这一层。
4. 新增 `sql/legacy/GatewayDemo.SqlServer2005.sql`，按 `SQL Server 2005` 兼容重写了网关自有库的建表脚本。
5. `GatewayDemo.Legacy.sln`、`GatewayDemo.Legacy.Core.csproj`、`GatewayDemo.Legacy.Web.csproj` 已经在本机通过离线 `MSBuild` 编译验证。

## 当前保持不变的功能基线
1. 设备识别与设备申请审批。
2. 整站访问控制，而不是只控登录页。
3. 同一设备的多站点授权。
4. 管理后台独立入口。
5. 审计日志。
6. 浏览器与现有官方 APP 统一走网关的接入能力。

## 当前需求边界

当前默认按 [需求边界说明.md](./需求边界说明.md) 推进：

1. 主需求：给现有官方 APP 套网关。
2. 次需求：浏览器和 APP 都走统一认证。
3. 非当前主需求：开放给第三方 APP 的自定义接入协议。

因此，自定义 `AppKey / AppSecret / HMAC` 这套能力在兼容版里继续保留，但当前只作为可选增强项，不作为第一优先级验收主线。

## 已按兼容要求调整的实现方向
1. 网关作为独立站点实现，不要求与原 ERP 页面框架同构。
2. 接口层允许按 `Web API2` 落地，离线依赖允许随交付包提供。
3. 反向代理默认按 `IIS ARR + URL Rewrite` 这类成熟组件落地，不再坚持代码自研代理。
4. 网关自有数据优先按 `SQLite` 设计，降低客户部署成本。
5. 安全策略和 IIS 承载方式按“更安全优先”落地。

## 仍需公司提供的联调资料
APP 这块目前不再是技术栈阻塞，但为了做到“不影响原有 APP 运行机制”，仍需要围绕**现有官方 APP**核对这些联调资料：

- 官方 APP 实际连接的企业站点地址 / 企业号 / 服务器地址填写规则
- 登录前初始化接口清单，例如 `sys.ashx`、`tenant_name`、`fileversion`
- 主登录接口路径与关键入参字段
- 登录后核心会话字段 `userToken / SessionKey` 的携带方式
- 需要优先覆盖的官方 APP 版本范围

在这份资料给到之前，我已经可以继续推进浏览器主流程、管理后台、审批流、审计、站点授权和代理层。
